# 云栖咖啡 · 门店经营看板（演示版）

一个纯静态的小型网站，包含两个栏目：

1. **销售看板**（`index.html`）—— 某家店铺在某个自然日内的销售额情况。
2. **员工工时**（`staff.html`）—— 每个员工的上下班打卡记录，以及以一个自然月为周期的工时统计。

界面简洁清晰，打开即可用，不需要安装依赖、不需要联网，所有数字都是**虚拟数据**。

## 如何打开

方式一（最简单）：直接双击 `index.html`，通过顶部导航在两个栏目之间切换。

方式二（推荐，本地服务器）：
```bash
node serve.js
# 浏览器访问 http://localhost:5178
```

## 一、销售看板

- **顶部日期选择**：`‹` / `›` 前后翻一天，或直接用日期选择器、`今天` 按钮。未来的日期会提示「该日期尚未发生」；早于开业日（2024-01-01）的日期会提示「店铺尚未开业」，日期选择器也不允许选到开业日之前。
- **五个核心指标**：当日销售额、订单数、客单价、售出商品件数、退款金额，每个都带环比（今天比昨天的**同一时段**，历史日期则整天对整天）。开业首日没有前一天数据，此时只显示说明、不显示涨跌幅。
- **分时走势**：0–23 点逐小时柱状图，可切换看「销售额 / 订单量 / 客单价」，最高的一根柱子高亮标记，鼠标悬停显示该小时的销售额、订单数和客单价。
- **支付方式**：微信、支付宝、会员储值、银行卡、现金的销售额占比环图。
- **分类销售**：现制饮品、烘焙、简餐、零售商品的销售额与件数占比。
- **热销商品**：当日销售额 Top 10，含单价、销量、销售额和占比。

状态栏会标注营业时间（07:00–22:00）。看「今天」时只统计到当前整点并显示「进行中」，页面每分钟自动刷新，跨小时后自动推进。

## 二、员工工时

- **顶部月份选择**：以自然月为周期，`‹` / `›` 翻月，或直接用月份选择器、`本月` 按钮。未来的月份会提示该月尚未开始；早于开业月的月份（2024-01 之前）会提示该月早于开业时间。
- **五个月度指标**：本月总工时、出勤人次、日均工时、加班总时长、每小时人效（本期销售额 ÷ 总工时），都带环比（本月进行中时对比上月**同期**）。开业首月没有上个月数据，此时只显示说明、不显示涨跌幅。
- **每日总工时**：按天统计全店打卡工时，工时最高的一天高亮，悬停显示当天在岗人数和姓名。
- **岗位工时占比**：按岗位（店长／咖啡师／后厨／收银服务等）汇总工时与人次。
- **员工工时汇总**：每位员工的出勤天数、总工时、日均工时、加班时长、迟到早退次数、整月出勤分布（色块越深工时越长）、对标准月工时的达成率。点击任意一行，下方切换为该员工的每日明细。
- **每日打卡明细**：日期、星期、班次、上班时间、下班时间、休息时长、当日工时、状态（正常／迟到／早退／加班／请假／休息）。今天的行会高亮，正在上班的班次标记为「进行中」。

### 工时口径

| 项目 | 规则 |
| --- | --- |
| 班次 | 早班 07:00–16:00、中班 11:00–20:00、晚班 13:00–22:00、全班 08:00–20:00、兼职班按需排 4–6 小时 |
| 工时 | 下班时间 − 上班时间 − 休息时长（早/中/晚班扣 1 小时，全班扣 1.5 小时，兼职班不扣） |
| 迟到 | 比排班上班时间晚到 6 分钟以上 |
| 早退 | 比排班下班时间早走 16 分钟以上 |
| 加班 | 比排班下班时间晚走 30 分钟以上，超出部分计入加班时长 |
| 月度工时 | 该员工当月所有出勤日的工时之和 |
| 参考工时 | 174 小时（21.75 天 × 8 小时）；本月进行中时按已过天数等比折算 |

本月进行中时只统计到今天，且今天的班次按「已工作时长」计入（并按比例扣除休息时间），所以当天的工时是实时的。

## 虚拟数据的生成规则

数据全部在 `data.js` 里生成，以「日期」或「员工 + 日期」为随机种子（确定性伪随机），所以**同一天／同一月每次打开结果完全一致**，不同日期各不相同。

门店自 `STORE.openDate`（默认 2024-01-01）开业，早于开业日期的数据不会生成、也不会展示，两个栏目的界面都会给出「尚未开业／早于开业时间」的提示。

**销售数据**（`buildDay`）：

- 按小时权重生成客流（早高峰、午高峰、下午茶、晚间依次衰减），周末整体上浮约 30%，周五上浮约 14%。
- 每单随机 1–3 件商品，商品按「品类基础占比 × 时段偏好 × 单品受欢迎度」抽取，因此早上烘焙多、中午简餐多。
- 按支付方式权重随机分配，最后汇总各维度，并随机产生少量退单。

**员工考勤数据**（`buildAttendance` / `getMonth`）：

- 全职员工按固定周休（每人两天，尽量错开以保证周末有人），兼职员工按每周约 3 天排班。
- 打卡时间在排班时间附近小幅浮动，偶尔迟到、偶尔晚走加班，全职员工小概率请假。
- 每人每天的班次由各自的排班偏好权重决定（例如店长多上全班、后厨多上早班）。

想调整门店设定，改 `data.js` 顶部的常量即可：

| 常量 | 作用 |
| --- | --- |
| `STORE` | 店名、**开业日期**、营业时间、整体生意规模（早于开业日期的数据一律不生成、也不展示） |
| `CATALOG` | 商品档案：名称、品类、单价、受欢迎程度 |
| `CAT_BASE` / `CAT_TIME_MIX` | 各品类的销售占比与时段偏好 |
| `HOUR_WEIGHT` | 一天 24 小时的客流曲线 |
| `PAYMENTS` | 支付方式及其占比 |
| `EMPLOYEES` | 员工名册：姓名、岗位、全职/兼职、周休日、班次偏好 |
| `SHIFTS` | 班次定义：上下班时间与休息时长 |
| `STANDARD_MONTH_HOURS` | 月度参考工时（默认 174 小时） |

## 接入真实数据

页面渲染与数据生成是分开的：`data.js` 负责取数，`app.js` / `staff.js` 只负责画界面。接后端时，用接口替换 `data.js` 里对应函数的返回值即可（保持结构一致），渲染代码不用动。

```js
// 一天的数据
{ totalSales, orders, items, netSales, refundAmount, refundCount, aov,
  hourly:     [{ hour, sales, orders }],                  // 0–23 点
  categories: [{ name, sales, qty }],
  payments:   [{ name, color, sales, orders }],
  products:   [{ name, cat, price, qty, sales }] }        // 按销售额倒序

// 一个月的数据
{ ym, year, month, daysInMonth, lastDay, partial,
  days:  [{ dateKey, day, weekday, hours, onDutyCount, onDuty, isToday }],
  staff: [{ id, name, role, type, workDays, restDays, leaveDays, totalHours,
            overtimeHours, lateCount, earlyLeaveCount, avgHours, longestDay,
            achievement, referenceHours,
            daily: [{ dateKey, day, weekday, kind, status, hours, ongoing,
                      rec: { shiftName, inMin, outMin, breakMin, hours, status, tags } }] }],
  totalHours, personTimes, overtimeHours, lateCount, earlyLeaveCount,
  activeStaff, avgPerStaff, avgOnDuty, avgDailyHours, byRole }
```

## 文件结构

```
sales-dashboard/
├── index.html   销售看板页面
├── staff.html   员工工时页面
├── data.js      共享数据层：销售与考勤的虚拟数据生成（无 DOM 依赖）
├── app.js       销售看板的渲染逻辑
├── staff.js     员工工时页的渲染逻辑

```
