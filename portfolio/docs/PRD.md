## 1. 背景与目标

### 1.1 背景

现有的项目说明散落在仓库 README、聊天记录和零散的截图中，缺少一个统一的对外入口。招聘方或合作方想了解“做过什么、怎么做的、能不能交付”，往往需要逐个仓库翻找。

### 1.2 产品目标

1. 用一个站点讲清楚三件事：我是谁、做过什么、怎么联系。
2. 每个项目都包含问题、做法、功能与复盘，而不是只放一张截图。
3. 站点本身也要能作为作品：可访问、响应式、无框架、断网可用。
4. 提供一个内容后台，非技术同学也能修改页面上的个人信息与项目摘要。

### 1.3 成功标准

| 指标 | 目标值 |
| --- | --- |
| 首屏可交互时间（本地） | < 1s |
| 运行时依赖 | 0 |
| 外部网络请求（页面加载） | 0 |
| Lighthouse 可访问性 | ≥ 95 |
| 横向滚动问题 | 375 / 768 / 1440 三档均为 0 |
| 内容修改到页面生效 | 保存后刷新即可见 |

## 2. 目标用户与场景

### 2.1 用户画像

| 角色 | 关注点 | 典型动作 |
| --- | --- | --- |
| 招聘方 | 能力边界、项目复杂度、代码质量 | 快速浏览项目 → 打开详情 → 查看源码 |
| 潜在合作方 | 能否解决具体问题、响应速度 | 看服务范围 → 提交需求 → 等回复 |
| 同行 / 读者 | 实现细节、踩坑记录 | 阅读博客 → 查看代码片段 |
| 站点所有者 | 内容维护成本 | 登录后台 → 修改信息 → 保存 |

### 2.2 核心用户旅程

1. 从 GitHub 或简历进入首页。
2. 首屏 5 秒内知道“这个人做什么、是否可合作”。
3. 进入项目列表，按类型筛选，打开项目详情。
4. 阅读“要解决的问题 / 我的做法 / 主要功能 / 回头再看”。
5. 通过联系页提交需求，或直接发邮件。
6. 所有者进入后台更新个人信息，刷新前台确认生效。

## 3. 范围

### 3.1 本期范围

- 首页、项目列表、项目详情、博客列表、文章详情、关于、联系七个页面。
- 项目筛选、文章搜索与标签筛选、文章目录高亮、阅读进度。
- 联系表单的本地校验与本地存储。
- 内容后台：个人信息、项目摘要、文章摘要的编辑与备份。
- 响应式布局、键盘可达、减少动效适配。
- 部署到 Vercel / Cloudflare Pages 并绑定访问地址。

### 3.2 不在本期范围

- 真实账号体系与多用户权限。
- 服务端数据库与跨设备实时同步。
- 评论、订阅邮件、支付。
- 多语言切换。
- 图片上传与 CDN 管理。

## 5. 功能需求

### FR-01 首页

| 项 | 说明 |
| --- | --- |
| 优先级 | P0 |
| 描述 | 展示姓名、定位、简介、精选项目、技能、最新文章与联系入口。 |
| 规则 | 精选项目取前 3 个；最新文章按日期倒序取前 3 篇；数据来自 `js/data.js`。 |
| 验收 | 首屏能看到姓名、一句话定位、两个主按钮；项目与文章卡片可点击进入详情。 |

### FR-02 项目列表与筛选

| 项 | 说明 |
| --- | --- |
| 优先级 | P0 |
| 描述 | 按分类筛选项目，显示每个分类的数量与筛选结果数量。 |
| 规则 | 分类由项目数据自动汇总；筛选状态同步到 URL 的 `category` 参数；方向键可在筛选项之间移动焦点。 |
| 验收 | 点击“浏览器扩展”后只剩 1 个项目；刷新后筛选状态保留；空分类显示空状态。 |

### FR-03 项目详情

| 项 | 说明 |
| --- | --- |
| 优先级 | P0 |
| 描述 | 展示项目背景、问题、做法、功能清单、技术栈、截图与复盘。 |
| 规则 | 通过 `id` 查询参数读取项目；不存在的 id 显示 404 状态页；有演示地址时显示“在线查看”。 |
| 验收 | 三个项目的详情均可打开；每个页面只有一个 h1；截图有 alt 文本。 |

### FR-04 博客搜索与标签

| 项 | 说明 |
| --- | --- |
| 优先级 | P1 |
| 描述 | 支持按标题、摘要、标签搜索，并按标签筛选。 |
| 规则 | 搜索输入防抖 120ms；置顶文章在无筛选时单独展示，且不重复出现在列表中；筛选结果数量通过 `aria-live` 播报。 |
| 验收 | 输入“扩展”只剩相关文章；清空后恢复全部；无结果时显示空状态与重置按钮。 |

### FR-05 文章详情

| 规则 | 目录根据 h2 / h3 自动生成；滚动时高亮当前章节；顶部显示阅读进度条。 |
| 验收 | 目录链接可跳转；滚动到第二节时对应目录项高亮；减少动效模式下内容完整。 |

### FR-06 关于页

| 项 | 说明 |

### FR-07 联系页与表单

| 项 | 说明 |
| --- | --- |
| 优先级 | P0 |

## 6. 非功能需求

### 6.1 响应式

- 断点：`< 640px` 单列，`640–899px` 两列，`≥ 900px` 三列。
- 任何页面不得出现横向滚动；表格与代码块在容器内横向滚动。
- 触控目标不小于 40 × 40px（文字链接除外）。

### 6.2 可访问性

- 每页一个 h1，标题层级不跳级。
- 提供“跳到主要内容”链接，键盘焦点始终可见。
- 所有图片有 alt，所有图标装饰性元素标记 `aria-hidden`。
- 表单控件有关联 label，错误通过 `role="alert"` / `aria-live` 播报。
- 正文与次要文字对比度 ≥ 4.5:1。
- 尊重 `prefers-reduced-motion`，关闭动画后内容照常可见。

### 6.3 性能与隐私

- 不使用框架、CDN、外部字体；页面总资源（不含截图）< 300KB。
- 星空背景使用 Canvas，标签页隐藏时暂停 requestAnimationFrame。
- 联系表单与后台数据只存储在浏览器本地，不上传服务器。

### 6.4 兼容性

- 最近两个版本的 Chrome、Edge、Firefox、Safari。
- 支持直接双击 HTML 打开；`file://` 下筛选参数同步失败时静默降级。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 本地后台不具备真实权限控制 | 数据可被同浏览器用户修改 | 文档明确演示性质；生产环境接入账号与 KV |
| 内容只存在 localStorage | 换设备看不到修改 | 提供导出 / 导入；后续接服务端 |
| 静态页面重复导航与页脚 | 改导航需改多个文件 | 接受重复，换取无 JS 也能完整阅读 |
| 部署平台差异 | 路径或缓存行为不一致 | 使用相对路径，禁用构建步骤，部署后逐页检查 |
