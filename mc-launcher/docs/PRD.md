## 1. 背景与目标

### 1.1 为什么做

在国内环境下载 Minecraft，「启动器」几乎是必需品，原因不在游戏本身，而在下载链路：

- 官方资源域名（`piston-data.mojang.com`、`libraries.minecraft.net`）在部分网络下很慢甚至不可达，20 多 MB 的客户端加一两百 MB 的资源文件可能卡在 0%。
- 想玩某个特定版本（比如同学在玩的 1.20.4、某个地图要求的 1.12.2），要自己找版本、找 Java，官方启动器还得先更新一遍并不需要的内容。
- 多个版本放进同一个目录会互相污染：资源索引、设置、存档混在一起，出问题后很难定位。

PCL2 这类启动器把上面三件事做顺了，但它们的使用体验仍有可改进处：安装流程的进度反馈粗糙、镜像切换要手动、失败原因常常只有一句「下载失败」。本项目想重做一版**以镜像下载为核心**的桌面启动器：源可切换、速度可见、失败可解释。

本期先把**纯净版（原版）**的安装链路做扎实：不碰 Forge / Fabric 的安装脚本，也不做加载器版本匹配。理由是先在一个变量更少的场景里把「下载链路 + Java + 启动 + 诊断」四件事做好。

在此之上，本期补上**内容下载中心**：Mod、整合包、材质包、光影四类内容，用模拟数据演示「挑内容 → 检查兼容性 → 与版本任务共用同一条下载队列 → 装进指定实例目录」。内容安装只把加载器当作**兼容性条件**（Mod 需要实例已有 Fabric / Forge 等标记），不提供独立的加载器安装向导。

### 1.2 产品定位

**一个先把「下载与启动」做对的 Windows Minecraft 启动器：多镜像并行、断点续传、按版本隔离，界面把每一步在做什么讲清楚。版本装原版，内容（Mod / 整合包 / 材质包 / 光影）按实例落位。**

明确不做的事：

- 不做游戏内的任何功能（不注入 Mod、不改游戏本体）。
- 不做服务器租用、账号交易、整合包商店。
- 不内置任何非官方分发的游戏文件；只从可配置的镜像站获取 Mojang 官方发布的版本清单与文件，内容元数据在演示阶段全部是本地模拟数据。

### 1.3 本期目标（演示阶段）

1. 把启动器的主要界面与主流程走通：看版本 → 选镜像 → 安装（模拟进度）→ 启动 → 看日志。
2. 桌面形态先按 Windows 单平台设计：路径、Java 检测、托盘、打开目录都只考虑 Windows。
3. 所有数据来自 `mock/` 下的模拟数据，界面标注「演示数据」，**不发起真实下载、不写真实 `.minecraft` 目录**；下载进度是定时器推进的假进度，但文件名、体积、速度量级都按真实清单取值，看起来可信。
4. 需求本身要能直接指导开发：每个功能有明确规则、边界与异常处理，验收项可逐条判断通过与否。

### 1.4 成功标准

| 指标 | 目标值 | 说明 |
| --- | --- | --- |
| 从打开到看到版本列表 | ≤ 1.5s | 模拟数据读取，不含真实网络 |
| 「安装 1.20.4」全流程点击次数 | ≤ 3 次 | 选版本 → 确认（默认源）→ 开始 |
| 内容安装全流程点击次数 | ≤ 3 次 | 选内容 → 选实例 → 开始 |
| 内容与版本任务 | 共用一条队列 | 下载中心不按类型拆页，暂停/继续/重试的规则完全一致 |
| 假进度的可信度 | 与本机真实下载观感一致 | 6～14MB/s 波动、文件粒度推进、可暂停继续 |
| 下载阶段的可见信息 | 速度 / 已下载 / 剩余 / 当前文件 / 源 | 缺一不可 |
| 可解释的失败 | 100% | 每个失败态都有原因 + 可执行的下一步 |
| 版本隔离的默认行为 | 开 | 每个版本一个独立实例目录 |
| 演示态触达率 | 100% | 空状态、下载中、校验失败、镜像超时、Java 缺失、启动崩溃六种状态都能在演示中复现 |

## 2. 用户与场景

### 2.1 用户画像

| 角色 | 关注点 | 典型行为 | 痛点 |
| --- | --- | --- | --- |
| 新手玩家 | 能不能一次装上、能不能玩 | 跟着同学进同一个版本，装完直接开 | 不知道 Java 是什么；下载卡住以为软件坏了 |
| 多版本玩家 | 版本互不干扰、切换要快 | 同时留 1.20.4、1.19.2、1.12.2 三个原版 | 资源与设置混在一起，存档找不到 |
| 低配 / 老旧机器 | 内存占用、启动参数 | 手动改内存、关掉花哨效果 | 启动器自己很吃内存 |
| 折腾型用户 | 可控性 | 自定义镜像、改 JVM 参数、看日志 | 日志在很深的目录里，出错不知道看哪 |

### 2.2 核心用户旅程

1. 打开启动器，左侧是已安装版本（首次为空），右侧是推荐版本与镜像状态。
2. 点「安装新版本」，列表里选 `1.20.4`（原版），直接进入确认页。
3. 确认页看到「需要下载 293MB / 1742 个文件 / 使用 BMCLAPI / 预计 40 秒」，源默认「自动」。
4. 开始安装：进度条、速度、当前文件名、剩余时间实时变化；中途可暂停、可继续。
5. 想加内容时点左侧「下载 → Mod」，按游戏版本与加载器过滤，选一项、挑一个兼容实例，下载任务进同一条队列，完成后在实例里显示「已安装」。
6. 完成后自动检测 Java，缺失时提示一键下载 JRE 21。
7. 点「启动」，游戏窗口出现；启动器收起到托盘，日志窗口可展开。
8. 下次打开，该版本在「最近使用」第一位，实例配置与上次一致。

### 2.3 环境约束

- 目标平台：**仅 Windows 10（1809+）/ 11，x64**。不做 macOS、Linux、ARM 与移动端。
- 界面适配：高 DPI（125% / 150% / 200%）下布局不破；系统深色模式可跟随。
- 网络：存在「完全不通官方源」「官方源慢但可用」「镜像不可信」三种情况，产品必须都能处理。
- 磁盘：单个原版版本含资源文件约 300MB～600MB（不同大版本差异大），需在安装前估算空间。
- 权限：默认装到用户目录（`%APPDATA%\.minecraft` 或自定义），避免 UAC 提权。

## 3. 范围

### 3.1 P0（演示阶段必须覆盖的界面与规则）

1. 版本列表与详情：正式版、快照、远古版；已安装 / 未安装状态区分。
2. 安装向导（三步）：选版本 → 选下载源（默认自动）→ 确认并开始模拟安装。
3. 镜像管理：内置官方源与两个镜像源，显示延迟与可用性，可手动切换、可测速。
4. 下载中心：任务列表、假进度、速度、当前文件、暂停 / 继续 / 取消、失败原因与重试。
5. 账号：微软、离线、第三方登录三类；主页启动卡里直接显示并切换当前账号。离线账号可改游戏内 ID（3～16 位字母数字下划线，UUID 由用户名派生），微软与第三方账号的名称由认证方同步、只读；真实登录仍为演示占位。
6. Java 管理：版本检测结果、按游戏版本推荐 Java（8 / 17 / 21）、缺失态提示。
7. 启动设置：内存、窗口尺寸、全屏模式启动、Java 版本（推荐自动匹配 / 指定运行时）、JVM 参数、是否显示日志窗口、版本隔离开关。
8. 实例目录：每个版本独立 `instances/<版本名>/`，根目录可在设置里改（演示中只显示模拟路径）。
9. 设置与主题：浅色 / 深色、语言（仅中文）、并发数与限速、默认安装路径。
10. 日志面板：模拟启动日志滚动、崩溃摘要与「复制诊断信息」。
11. 内容下载中心：左侧「下载」展开后分纯净版 / Mod / 整合包 / 材质包 / 光影五个入口；安装任务不再占侧栏，改成右下角的悬浮球，有进行中或失败任务时显示任务数与总体进度，点开是只列任务的面板，并可从面板跳到各下载分类。内容按游戏版本与加载器过滤，安装时校验目标实例，完成后写入对应目录并出现在实例配置里。

### 3.2 P1（评审后再排）

- 微软 OAuth 登录（需应用注册与 client id）、正版皮肤展示。
- 加载器独立安装向导（Fabric / Forge / NeoForge 的版本列表与安装脚本）。
- 内容版本选择（同一 Mod 的多个历史版本）、依赖树解析与冲突提示。
- 多实例快照与回滚、配置导入导出、启动参数预设。
- 自动更新、增量更新清单、网络诊断工具、托盘常驻与开机自启。

### 3.3 不做

| 功能 | 原因 | 说明 |
| --- | --- | --- |
| 独立的加载器安装向导 | 本期只做「纯净版 + 内容」 | Mod 只把加载器当兼容条件；Fabric / Forge 的版本列表与安装脚本留到 v2 |
| 内容商店、付费内容、云端收藏 | 需要账号、支付与后端 | 本期内容目录只是本地模拟数据 |
| 内置或分发游戏本体 | 版权风险 | 只从用户配置的源下载官方发布的文件 |
| 账号共享 / 离线皮肤站账号池 | 违反 Minecraft 用户协议 | — |
| 服务器租用、联机大厅 | 需要后端与运营 | 产品性质会变 |
| macOS / Linux / 移动端 / ARM | 本期只做 Windows x64 | 路径、Java、托盘都要另写一套 |
| 真实下载（本期） | 演示阶段用假进度 | v1 再接入真实清单与 HTTP 下载 |

### 3.4 迭代路线

- **v0（本阶段）**：Windows 静态界面演示 + 模拟数据，覆盖 P0 全部界面与六种演示状态；假进度；内容下载中心（Mod / 整合包 / 材质包 / 光影）跑通「过滤 → 兼容性 → 队列 → 落位」。
- **v1**：接入真实版本清单（`version_manifest_v2.json`）与真实下载（HTTP Range + SHA1 校验），本地状态落 SQLite；Java 运行时自动下载。
- **v1.1**：崩溃诊断增强、增量更新、托盘与开机自启、内容目录接真实平台 API（Modrinth）。
- **v2（若需要）**：加载器独立安装向导、依赖冲突解析、微软登录。

## 4. 功能需求

### F1 版本列表

- 数据来源：版本清单（演示为 `mock/versions.json`，真实为镜像的 `version_manifest_v2.json`）。
- 列表字段：版本号、类型（正式 / 快照 / 远古）、发布时间、是否已安装、占用空间。
- 分组：已安装、正式版、快照、远古版；默认展开「已安装」与「正式版」。
- 排序：发布时间倒序（默认）、版本号、占用空间。
- 筛选：搜索框按版本号模糊匹配；类型多选；「只看已安装」开关。
- 空状态：没有任何版本时显示引导「安装第一个版本」，并给出推荐版本（最新正式版）。
- 性能：500 条数据滚动不卡顿（虚拟滚动或分批渲染）。
- 版本详情（右侧）：版本号、发布时间、需要的 Java 主版本、预计体积、文件数、是否已安装、该版本实例的最近启动时间。
- 进入安装：点任意一行（或用上下键选中后按 Enter）进入「版本安装选项」页，在那里决定加载器与附加组件，见 F2b。

### F2 快速安装向导（只要纯净版）

三步，任何一步都可以返回，已选内容保留：

1. **选版本**：默认选中最新正式版；显示该版本需要的 Java 版本与预计体积。已安装的版本在该步出现「已安装」标记，选中后按钮变为「打开实例」。
2. **选下载源**：默认「自动」，展示每个源的延迟与状态；也可手动指定某个镜像。此步折叠在确认页内，不强制单独点一次。
3. **确认与开始**：汇总「版本 / 源 / 文件数 / 总大小 / 预计时间 / 目标目录 / 磁盘剩余」，点「开始安装」后进入下载中心，进度为模拟推进。确认页的「加载器」一行给出「去选加载器 / 高清修复」入口，跳到 F2b 的安装选项页。

规则与边界：

- 同名版本已存在时，提示「该版本已安装」并给两个选择：打开已有实例、重新安装（覆盖版本文件，保留存档与配置）。实例模型是「一个版本一个实例」，不能在同一版本下并存两个目录。
- 磁盘剩余空间不足（小于总体积 1.2 倍）时禁止开始，提示具体差值。
- 快速向导只处理游戏本体；需要加载器、高清修复或光影支持时走 F2b。
- 演示阶段不写真实文件：`目标目录` 显示模拟路径 `C:\Users\Demo\AppData\Roaming\minecraft\`，鼠标悬停提示「演示路径，不会写入」。

### F2b 版本安装选项页（加载器 / 高清修复 / 光影支持）

从版本列表点一行进入，是「装什么」的唯一决策页。页面分左右两栏，左侧按顺序给四块内容，右侧固定显示安装摘要：

1. **游戏本体**：版本号、类型、发布时间、所需 Java、本体体积与文件数、目标目录。任何选项都会装。
2. **Mod 加载器（单选）**：不装加载器（最轻）、Fabric、Forge、NeoForge。每个选项写明用途与追加体积 / 文件数。
3. **高清修复与光影**：OptiFine（高清修复）、Sodium（性能优化）、Iris（光影支持）三个开关。
4. **下载源**：自动（推荐）或手动指定可用镜像；加载器与附加组件跟随同一个源下载。

右侧摘要：加载器、附加组件、本体 / 追加体积、合计体积与文件数、预计耗时、下载源、磁盘剩余，以及「开始安装」「返回版本列表」。

**可用性规则**

| 选项 | 支持的版本 / 加载器 | 不可用时的文案 |
| --- | --- | --- |
| Fabric | 发布日期 ≥ 2018-12-01 | 「该版本发布时还没有 Fabric，只能用原版」 |
| Forge | 发布日期 ≥ 2013-01-01 | 同上，替换加载器名 |
| NeoForge | 发布日期 ≥ 2023-06-01（1.20.1 起） | 同上，替换加载器名 |
| OptiFine（高清修复） | 正式版、发布日期 ≥ 2014-01-01；加载器为原版或 Forge | 「需要 原版 / Forge 加载器」或「快照与远古版没有 OptiFine 构建」 |
| Sodium（性能优化） | 仅 Fabric | 「需要 Fabric 加载器」 |
| Iris（光影支持） | 仅 Fabric，自动带上 Sodium | 「需要 Fabric 加载器」；勾选 Iris 后 Sodium 显示「随 Iris 一起安装」并锁定 |

交互规则：

- 切换加载器时，自动取消不再支持的附加组件，不弹二次确认；界面上被禁用的开关直接写明原因，不能点。
- 勾选 Iris 自动勾选并锁定 Sodium；取消 Iris 后 Sodium 恢复可手动切换。
- 页面上所有选择都是本地草稿，只有「开始安装」会入队；返回版本列表不保留草稿（再次进入时按已有实例初始化）。
- 版本已有实例时，页面按该实例的加载器与附加组件初始化，并提示「再次安装会覆盖版本文件、保留 saves/ 与 config/，新选择会应用到已有实例」。
- 磁盘剩余不足总体积 1.2 倍、或场景为「镜像不可用」且使用自动源时禁用「开始安装」并给出原因。
- 加载器与附加组件追加在版本文件之后下载（清单里排在最后），体积与文件数计入同一任务；任务卡片标出加载器与附加组件。

**演示边界**

- 不解析、不执行真实的 Forge / Fabric 安装器，也不下载加载器本体；上述文件只是写进假清单的模拟条目。
- 演示不区分加载器版本号（如 Fabric Loader 0.16.9），只演示「装不装、装哪个」这一层。

### F3 镜像与下载

这是本产品的核心，需求要写到「换谁都能实现」。

> 演示阶段：界面按下面的字段、状态与文案完整呈现，但**不发起任何真实请求**；进度、速度、当前文件名由模拟器按真实清单的量级推进，暂停 / 继续 / 失败 / 重试都是真实的状态机，只是数据源是假的。

**镜像源定义**

| 字段 | 说明 |
| --- | --- |
| id | `mojang` / `bmclapi` / `mirror-cn` / `custom` |
| baseUrl | 源地址前缀，用于替换官方资源的域名与路径 |
| 延迟 | 最近一次测速的 RTT（ms），用于展示与自动选择 |
| 吞吐 | 最近一次实测速度（MB/s） |
| 状态 | 可用 / 不稳定 / 不可用（连续 3 次失败判定） |
| 优先级 | 用户排序，自动模式下按优先级 + 实测表现选择 |

**选择策略（自动模式）**

1. 启动安装时对可用源做一次轻量探测（清单文件 HEAD 请求，超时 2s）。
2. 按「延迟权重 0.6 + 历史成功率 0.4」排序，取第一名作为主源，第二名为备用源。
3. 单个文件失败 3 次（指数退避 1s / 3s / 8s）后切换到备用源重下该文件，已下载的分片不丢。
4. 主源连续失败 10 个文件则整体切换到备用源，并在下载中心提示「已切换到 XX 源，原因：连续超时」。
5. 全程记录每个源的实际速度与失败次数，完成后回写到源统计。

**下载规则**

- 每个任务先取文件清单（路径、大小、SHA1），逐个下载并校验 SHA1，校验失败视为该文件失败，按上面的重试策略处理。
- 并发：默认 8 个文件同时下载，可在设置中改为 1～16；单文件内不做分片（Minecraft 的文件普遍较小），但对 > 20MB 的资源包启用 4 分片 Range 下载。
- 限速：可选「不限速 / 5 / 10 / 20 MB/s」，限速只影响总带宽分配，不改变并发数。
- 进度信息：总进度（字节 + 文件数双轴）、瞬时速度、平滑速度（3 秒滑动平均）、剩余时间、当前文件名、当前源。
- 控制：暂停（保留分片与已完成文件）、继续、取消（二次确认，询问是否保留已下载文件）。
- 完成后：校验清单完整性 → 写入版本 JSON → 刷新版本列表 → 自动检测 Java。

**失败态与文案**

| 场景 | 判定 | 提示 |
| --- | --- | --- |
| 全部源不可达 | 探测阶段全部超时 | 「所有下载源都连不上。检查网络后重试，或在设置里换一个镜像」 |
| 单文件 404 | HTTP 404 | 「镜像缺少文件 xxx，已切换到备用源」 |
| 校验失败 | SHA1 不一致 | 「文件下载不完整，正在重新下载（第 2 次）」 |
| 磁盘写满 | 写入异常 / 剩余空间为 0 | 「磁盘空间不足，还需要 120MB」 |
| 清单过期 | 版本 JSON 与清单不符 | 「版本信息已更新，请重新安装该版本」 |

### F4 Java 运行时

- 检测顺序：项目内置 JRE → 用户配置的 Java 路径 → `JAVA_HOME` → `PATH` 中的 `java` → 常见安装目录（`C:\Program Files\Java`、`C:\Program Files\Eclipse Adoptium`、`C:\Program Files\Microsoft\jdk-*`）。
- 判定可用：能执行 `java -version` 且主版本 ≥ 需求版本（1.17+ 需要 17，1.20.5+ 需要 21，旧版本用 8）。
- 多个可用时选最匹配的（不选过高版本，避免老版本反射类问题）。
- 缺失时：展示「需要 Java 21，当前只有 Java 8」，给「下载 JRE 21（约 45MB）」与「选择本地 Java」两个入口。
- 自定义路径需校验：目录下存在 `bin\java.exe`（Windows），并提供「浏览文件夹」选择器。

### F5 启动与实例

- 实例模型：默认一版本一实例，目录 `instances/<版本名>/`，内含 `saves/`、`config/`、`logs/`、`screenshots/`；装过内容的实例另有 `mods/`、`resourcepacks/`、`shaderpacks/`。
- 实例带 `loader` 字段（`vanilla` / `fabric` / `forge` / `neoforge`）：纯净版安装写 `vanilla`，整合包会带自己的加载器；Mod 只能装进加载器匹配的实例。
- 实例配置里列出已安装内容，可以逐项卸载（演示只改状态，不删文件）。
- 启动前检查（缺一不可，逐项显示状态）：
  1. 版本文件完整（清单比对）；
  2. Java 可用且版本匹配；
  3. 内存设置合理（≥ 1024MB 且不超过物理内存的 70%）；
  4. 目标目录可写；
  5. 未登录时使用离线用户名（需符合 `^[A-Za-z0-9_]{3,16}$`）。
- 启动参数：内存（-Xmx / -Xms 联动或独立）、窗口尺寸、全屏、JVM 额外参数（高级，折叠）、游戏参数。
- 启动后：启动器最小化到托盘，日志窗口浮出（可关）；游戏退出后回到主界面并显示「本次游戏时长 32 分钟」。
- 崩溃处理：读取最后 200 行日志做特征匹配（`OutOfMemoryError`、`Java 版本不符`、`OpenGL 初始化失败`、`版本文件缺失`、`资源索引损坏`），给出中文摘要与建议，提供「复制诊断信息」按钮（脱敏后的日志 + 环境信息，仅复制到剪贴板，不上传）。

### F6 账号

- 主页启动卡「当前账号」：下拉按微软 / 离线 / 第三方登录分组列出全部账号，选中即切换，只影响下次启动；右侧入口打开账号管理弹窗。
- 离线账号：用户名即游戏内 ID，可在主页直接改（3～16 位字母数字下划线）；UUID 由用户名派生，改名后 UUID 同步变化，同一名字始终得到同一 UUID。可建多个离线账号随时切换。
- 微软账号与第三方账号：名称由认证方（微软账号中心 / 外置登录服务器）同步，界面只读，不提供改名输入；改动只能回对应平台修改后重新登录。
- 微软账号：展示「登录」按钮与 OAuth 流程说明；演示阶段点击后进入「演示态」提示，不发起真实授权。
- 第三方登录：对接 Yggdrasil / authlib-injector 一类外置登录，列表里显示来源服务器名（演示态同样不联网）。
- 账号列表：头像（离线用首字母占位）、名称、类型标签、当前选中标记、删除（需二次确认）。
- 隐私：不保存密码；真实实现中令牌存系统凭据库或加密文件，日志中不得出现令牌。

### F7 实例与文件

- 实例卡片：名称、版本、占用空间、最后启动时间、状态标签（可用 / 文件缺失）。
- 操作：启动、打开目录、编辑配置、复制实例、删除（二次确认，勾选「同时删除存档」）。
- 文件浏览：只读展示 `saves/`、`logs/`、`screenshots/` 的文件列表与大小；演示阶段为模拟路径与模拟条目。

### F8 日志与诊断

- 日志窗口：自动滚动、暂停滚动、按级别过滤（INFO / WARN / ERROR）、关键字搜索、复制、另存为。
- 诊断摘要：崩溃时在顶部显示 3 行以内的结论 + 4 条可选建议。
- 环境信息：启动器版本、系统版本、Java 版本、分配内存、实例路径、最后 3 次启动结果。

### F9 设置

- 通用：语言（中文）、主题（浅色 / 深色 / 跟随系统）、启动时检查更新（演示关）。
- 下载：默认源（自动 / 指定）、并发数、限速、是否保留已取消任务的临时文件。
- 启动：默认内存、默认窗口尺寸、全屏模式启动、Java 版本（第一项「使用推荐 Java」，其余列已检测到的运行时）、是否显示日志窗口、退出后是否保留实例进程。
- 存储：默认安装路径（可手填，也可从「浏览…」的候选目录里挑；保存时校验 Windows 绝对路径，非法值当场标「待修正」并拒绝保存）。候选目录弹窗里换一块盘时，卡片高亮与底部「将改为」摘要立即跟着变，并写明已有实例不会跟着搬；选完回到设置页会留下一条「尚未保存」提示和「立即保存」按钮，顶部保存条同步闪一下，避免用户以为已经生效。此外显示各实例占用、可一键打开目录、清理缓存（日志与临时文件）。
- 关于：版本号、开源许可、镜像来源说明、「本页数据为演示数据」声明。

### F10 内容下载（Mod / 整合包 / 材质包 / 光影）

左侧「下载」是可展开分组，展开后五个入口：纯净版、Mod、整合包、材质包、光影。安装任务改为右下角的悬浮球：有进行中或失败的任务时显示任务数量与总体进度，点开是一块**只列任务**的悬浮面板，不打断当前页面；面板里可以暂停 / 继续单个任务，底部提供纯净版、Mod、整合包、材质包、光影五个跳转入口和「打开完整安装任务页」。没有需要关注的任务时悬浮球收起，完整任务页仍可从主页快捷入口和分类页顶部的「安装任务」标签进入。四个内容分类共用一套列表页，只在数据与文案上区分。

**列表与筛选**

- 卡片字段：封面（首字 + 色相）、名称、作者、版本号、简介、标签、加载器、支持的游戏版本、下载量、体积、文件数、更新时间、可安装到哪些实例。
- 筛选：关键字搜索（名称 / 作者 / 描述 / 标签 / 类型名）；游戏版本下拉（只对 Mod 与整合包显示，材质包与光影不限版本）；Mod 页另有两个下拉——加载器（Fabric / Forge / NeoForge，选项从目录数据推导）与类型（性能优化 / 玩法拓展 / 辅助工具 / 视觉美化），两者可与关键字、游戏版本、「只看已安装」组合，切换分类时保留选择但不参与材质包与光影的过滤；排序（下载量 / 最近更新 / 体积）；「只看已安装」。
- 每个分类顶部有「已安装 N 项」区块，列出所在地、安装时间、体积与卸载入口。
- 空状态：给「重置筛选」，并说明为什么没有结果（搜索、版本、只看已安装）。

**安装流程**

1. 点「安装」打开确认弹窗：名称、作者、体积、文件数、落位目录、下载源、依赖清单。
2. Mod / 材质包 / 光影：选择目标实例，按「游戏版本 → 加载器」校验，不兼容的实例禁用并写清原因。
3. 整合包：不选实例，安装完成后新建一个独立实例（重名自动加 `#2`），实例的版本与加载器由整合包决定。
4. 磁盘不足时禁止开始并写出还差多少；光影额外提示需要 Iris / OptiFine 才能加载。
5. 确认后进入下载中心，任务与版本安装共用队列与暂停 / 继续 / 重试规则。
6. 完成时写入实例（整合包则先建实例），刷新「已安装」状态与实例配置，并追加一条日志。

**兼容性规则**

| 内容类型 | 游戏版本 | 加载器 | 落位目录 |
| --- | --- | --- | --- |
| Mod | 必须命中 `mcVersions` | 必须命中实例的 `loader` | `instances/<实例>/mods/` |
| 整合包 | 包自带 `mcVersion` | 包自带 `loader` | 新建实例，`mods/` |
| 材质包 | 不限 | 不限 | `instances/<实例>/resourcepacks/` |
| 光影 | 不限 | 需要 Iris / OptiFine（仅提示） | `instances/<实例>/shaderpacks/` |

- 版本对得上但加载器不对时，给一个「给这个实例标记 Fabric（演示）」的入口，补上标记后即可安装；这是演示用的捷径，真实实现要走加载器安装向导。
- 同一 Mod 装进同一个实例只允许一份；装到第二个实例是允许的。
- 依赖（如 JEI 需要的配置库）跟随主文件一起下载，并计入体积与文件数。

## 5. 信息架构与界面

单窗口，左侧导航 + 主区域，顶部固定账号与全局状态栏。

| 页面 | 目标 | 关键区域 | 必须实现的状态 |
| --- | --- | --- | --- |
| 主页 | 一眼看到「玩什么」 | 最近实例大卡、当前账号切换、版本更新提示、镜像状态条、快捷操作 | 无实例 / 有实例、镜像异常、离线改名非法 |
| 版本与安装 | 选版本、装版本 | 版本表格、筛选栏、右侧详情、版本安装选项页（加载器 / 高清修复 / 下载源）、三步快速向导 | 空列表、加载中、加载失败、已安装、加载器不可用、磁盘不足 |
| Mod / 整合包 / 材质包 / 光影 | 给实例加内容 | 分类标签、筛选栏、内容卡片网格、已安装区块 | 空结果、无兼容实例、已安装 |
| 下载中心 | 看进度、管任务 | 任务列表、假进度、速度、当前文件、日志片段 | 进行中、暂停、失败、校验失败、已完成 |
| 实例 | 管已有版本 | 实例卡片网格、配置抽屉 | 空实例、目录缺失 |
| 设置 | 调参数 | 分组表单 + 保存条 | 校验错误、保存成功 |
| 日志 | 排错 | 日志滚动区、过滤栏、诊断卡片 | 无日志、崩溃摘要 |

交互约定：

- 所有耗时操作（探测、下载、校验、启动）都有进行中状态，超过 1.5 秒必须出现进度或文案，禁止静默。
- 危险操作（取消任务、删除实例、清理缓存）一律二次确认，并写清后果。
- 每个失败提示固定三段式：发生了什么 → 可能的原因 → 可以做什么。
- 键盘：Tab 可遍历所有控件；表格支持上下键切换行、Enter 打开；Esc 关闭抽屉与对话框。
- 深色主题下正文对比度 ≥ 4.5:1；减少动态效果时关闭速度曲线动画与进度条流光。

**模拟规则**

- 下载进度用 `requestAnimationFrame` / 定时器推进，速度在 6～14 MB/s 之间波动（正弦 + 噪声），每 400ms 更新一次。
- 「安装」按钮触发的任务按真实文件粒度拆分（先客户端、再库、最后资源），文件名取自清单，保证「当前文件」看起来是真的。
- 校验阶段耗时按文件数比例模拟（约 1.5 秒），成功后把版本标记为已安装并写入实例。
- 内容任务的基线速度按类型给值（Mod 约 1.9 MB/s、整合包 2.6 MB/s、材质包 2.2 MB/s、光影 1.7 MB/s），明显低于版本文件；文件清单按真实目录形态生成（Mod 是主文件 + 依赖，整合包是 manifest + 一串 `.jar`，材质包与光影是单个压缩包）。
- 已安装内容与实例的对应关系写在 `state.content` 里，卸载只删除这一条记录。
- 时间统一用「距今 N 分钟 / 小时 / 天」的相对格式，避免演示时日期过期。

**假进度的可信度要求**

1. 速度曲线不许是直线：目标速度 ±30% 波动，卡顿时可以短暂掉到 0 再爬升。
2. 文件切换要有瞬间停顿（50～150ms），否则像在播动画而不是下载。
3. 总进度按字节推进，文件计数按整文件跳变，两者不要求严格同步。
4. 校验阶段单独一条文案（「正在校验文件 605 / 1742」），不与下载共用进度条。
5. 暂停后所有数字立即冻结；继续时从冻结值接着走，不重算、不回退。
6. 完成时先到 100% 并停留 0.5 秒，再切到「安装完成 · 打开实例」，避免一闪而过。
7. 关闭再打开演示页，进行中的任务保持当时的进度（存 localStorage），不从头开始。

## 12. 术语表

| 术语 | 含义 |
| --- | --- |
| 版本清单 | `version_manifest_v2.json`，列出所有游戏版本及其元数据地址 |
| 版本 JSON | 单个版本的完整描述：库文件、资源索引、主类、启动参数 |
| 纯净版 / 原版 | 只装 Mojang 官方发布的游戏本体，不含 Forge / Fabric 等加载器与 Mod |
| 加载器 | 让游戏能读取 Mod 的中间层；本期可选 Fabric / Forge / NeoForge |
| 高清修复（OptiFine） | 第三方优化补丁，集合光影、高清贴图与渲染优化；闭源，和 Fabric 路线互斥 |
| 版本隔离 | 每个版本使用独立的游戏目录，配置与存档互不影响 |
| 镜像源 | 转发官方资源的第三方站点，用于改善国内下载速度 |
| 秒传 | 清单中已存在且校验通过的文件直接跳过，不重复下载 |
| 校验 | 对下载完成的文件计算 SHA1 与清单比对 |
| 内容 | Mod、整合包、材质包、光影四类资源的统称；元数据（名称、作者、版本、兼容范围）在演示阶段全部来自本地模拟目录 |
| 加载器 | Fabric / Forge / NeoForge 等用于加载 Mod 的运行环境；本期只作为实例上的一个标记参与兼容性判断 |
| 整合包 | 打包好的一组 Mod + 配置 + 加载器版本，安装时新建独立实例 |
