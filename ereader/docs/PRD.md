## 1. 背景与目标

### 1.1 为什么做

电子书文件散落在下载目录里，打开方式要么是沉重的全功能阅读软件，要么是必须登录、联网、上传文件的在线服务。想读一本自己买的 EPUB，不应该先注册账号。

### 1.2 产品定位

**一个打开就能用的本地阅读器：EPUB 与 TXT 都在本机解析，书在本地，进度也在本地，不登录、不上传。**

不做书城，不做社区，不做账号体系。产品的价值在「读」这一件事上做得足够顺。

### 1.3 MVP 目标

1. 拖进来就能读：选中文件后 3 秒内出现正文。
2. 能完整读完一本：目录跳转、章节切换、字号与主题都可用。
3. 下次打开回到原处：进度误差不超过一屏。
4. 两种格式都能进：EPUB 与 TXT 走同一个导入入口，解析结果结构一致（章节 + 段落）。

### 1.4 成功标准

| 指标 | 目标值 |
| --- | --- |
| 5MB 中文 EPUB 从导入到可读 | ≤ 3s |
| 重新打开后的位置偏差 | ≤ 1 屏 |
| 运行时依赖 | 0 个（解压用浏览器内置能力） |
| 深色主题正文对比度 | ≥ 4.5:1 |
| 首次使用到读完第一章的操作步数 | ≤ 3 步 |

## 2. 目标用户与场景

### 2.1 用户画像

| 角色 | 关注点 | 典型行为 |
| --- | --- | --- |
| 碎片时间读者 | 打开快、记得住进度、不登录 | 午休或睡前在电脑上读十几页，第二天接着读 |
| 技术书读者 | 目录清晰、字号可调、代码块不串行 | 跳章查资料，反复回看某几节 |
| 学生 / 教师 | 分发的 EPUB 能直接用，不折腾 | 从群文件里拿到书，拖进去就读 |
| 隐私敏感用户 | 文件不外传 | 断网使用，关掉页面不留服务器记录 |

### 2.2 核心用户旅程

1. 打开应用，看到空书架和一句「把 EPUB 拖到这里」。
2. 拖入一本 EPUB，书架出现封面、书名、作者、进度 0%。
3. 点击打开，正文直接可读，右上角能开目录。
4. 从目录跳到第 3 章，调大字号、切成深色主题。
5. 关闭窗口。
6. 第二天打开应用，书还在书架上，点开就是昨天那一页。

## 3. 范围

### 3.1 本期范围（P0）

1. 本地文件导入与解析：EPUB（EPUB 2/3 可重排）与 TXT 两种格式，同一个入口、同一套书架数据。
2. 书架：封面、书名、作者、格式、进度、最近阅读时间。
3. 阅读视图：章节渲染 + 上下章切换 + 滚动阅读。
4. 目录：EPUB 读 `nav.xhtml` / `toc.ncx`，TXT 按章节标题切分；跳章并高亮当前章节。
5. 进度记忆：章节 + 章节内位置锚点，关闭后可恢复。
6. 阅读设置：字号、行距、页宽、三套主题，设置持久化。
7. 异常兜底：损坏文件、加密 EPUB、缺封面、缺目录、TXT 编码异常都有明确提示。
8. 桌面安装：可安装为 PWA，安装后离线可用，双击 `.epub` 直接进入阅读（Chrome / Edge）。此项仍在排期，见 3.3。

### 3.2 不在本期范围

| 功能 | 为什么先不做 |
| --- | --- |
| 移动端与触屏适配 | 产品定位为桌面应用，本期只保证桌面窗口可用 |
| 账号、云同步、多端同步 | 需要后端与登录体系，价值晚于「能读」 |
| 在线书城、书源抓取 | 版权与合规风险，产品性质会变 |
| 高亮、笔记、批注 | 需要稳定的位置锚点，放在 v0.2 |
| PDF、漫画、扫描版 | 排版模型不同，等于另一个产品 |
| 固定版式（fixed layout）EPUB | 要处理 viewport 与双页缩放，成本高 |
| 跨书全文搜索、朗读、翻译、词典 | 依赖全文索引或第三方服务 |
| 竖排、Ruby 注音、自定义字体嵌入 | 长尾排版需求，等真实反馈 |

### 3.3 版本路线

- **v0.1（本期）**：导入、书架、阅读、目录、进度、设置、兜底。
- **v0.2**：高亮与笔记、章节内搜索、阅读统计。
- **v1.0**：可选账号与同步、多设备续读、导出笔记。

### 3.4 迭代记录

| 版本 | 时间 | 变化 | 结论 |
| --- | --- | --- | --- |
| v0 | D1 | 界面演示：书架、阅读、目录、设置全部由 `js/mock.js` 伪造，导入只有模拟动画 | 交互骨架可用，但读不了真实文件，不满足「打开就能用」 |
| v1（当前） | D2–D3 | 自研 ZIP 读取 + OPF / NAV / NCX 解析（`js/epub.js`）；新增 TXT 解析（编码识别、章节切分、元数据行）；导入结果落书架并持久化；目录跳章与进度恢复接入真实章节 | 核心读链路成立，EPUB 与 TXT 可混放；下一轮补 IndexedDB、PWA 与图片资源 |

v0 → v1 的关键改动是把正文数据源从 `mock.js` 换成解析结果：上层书架、阅读、目录、进度代码没有重写，只把数据形状统一成 `{ chapters: [{ title, blocks }] }`。

## 4. 功能需求

### F1 导入与解析

- 入口：工具栏「导入文件」按钮 + 整页拖拽区，支持多选。
- 格式：`.epub` 与 `.txt` 两种；不支持的扩展名直接提示「只支持 .epub 或 .txt 文件」，不进入解析。
- EPUB 流程：中央目录 → `META-INF/container.xml` → OPF（标题、作者、manifest、spine）→ `nav.xhtml`，退回 `toc.ncx`；任一步缺失只降级对应字段，不让整本书失败。
- TXT 流程：先判编码（BOM → UTF-8 严格解码 → GBK 兜底），开头「书名：/ 作者：」行当元数据读掉；再按「第 N 章 / 楔子 / 番外 / chapter N / Markdown 标题」切章，识别不到标题时按每 40 段一节切开。
- 两种格式产出一致的数据形状：`{ title, author, genre, chapters: [{ title, blocks }] }`，书架与阅读视图不区分来源。
- 去重：同一文件（文件名 + 大小 + 修改时间派生 id）重复导入时提示「这本书已经在书架上了」，不产生第二条记录。
- 失败提示要具体：「这个文件不是有效的 EPUB（找不到 ZIP 目录）」「这本书带加密保护（DRM），暂不支持」「没有读到正文内容」。

### F2 书架

- 卡片展示封面（缺封面时用书名首字生成占位）、书名、作者、格式标签（EPUB / TXT）、进度百分比。
- 排序：默认按最近阅读时间倒序，可切「最近添加」。
- 操作：打开、删除（需二次确认，删除同时清理本地文件）。
- 空状态：一句引导文案 + 导入按钮，不展示空白网格。

### F3 阅读视图

- 正文在独立容器内渲染，隔离原书样式，避免与产品 UI 冲突。
- 滚动阅读；上下章用按钮、方向键、点击左右边缘三种方式触达。
- 顶部显示书名与章节名，底部显示本章进度与全书进度。
- 沉浸模式：滚动时隐藏工具栏，点击中部或按 Esc 恢复。

### F4 目录

- 右侧抽屉，层级不超过 2 级时全部展开，更深层级按需展开。
- 当前章节高亮，切换章节后同步。
- 章节来源：EPUB 的 `nav.xhtml` → `toc.ncx` → 按 spine 生成「第 N 节」；TXT 用切分出的章节标题（没有标题时用文件名或「第 N 节」）。
- 点击目录项直接跳到该章开头，抽屉关闭后焦点回到目录按钮。

### F5 进度与记忆

- 记录粒度：章节序号 + 章节内块序号 + 块内比例（详见 `TECH_DESIGN.md` 4.4）；全书百分比只用于书架展示，预留 CFI 字段给 v0.2。
- 保存时机：翻章、滚动停止 1 秒、页面隐藏、关闭前。
- 恢复：打开书直接定位，不只落到章节开头。
- 书架显示全书进度，取章节序号加权估算。

### F6 阅读设置

- 可调：字号（5 档）、行距（3 档）、页宽（窄 / 中 / 宽）、主题（浅色 / 深色 / 护眼）。
- 生效范围：全局，写本地存储，换书不丢。
- 调整后保持当前位置，不跳回章节开头。

### F7 键盘与无障碍

- Tab 顺序：工具栏 → 目录 → 设置 → 正文；抽屉打开时焦点锁在抽屉内，Esc 关闭并归还焦点。
- 方向键 / PageUp / PageDown 翻动，Home / End 跳到本章首尾。
- 所有图标按钮有可读名称，进度用文本 + 进度条双重表达。

### F8 异常兜底

| 场景 | 期望表现 |
| --- | --- |
| 文件损坏或不是 ZIP | 「这个文件不是有效的 EPUB」，保留书架其他书 |
| 加密 / DRM | 明确提示不支持，不尝试解密 |
| 缺封面 | 首字占位图，不出现破图 |
| 缺目录 | 按 spine 生成章节列表 |
| 图片过大 | 章节可读，图片按容器宽度缩放 |
| 存储写满 | 提示清理旧书，不丢当前进度 |

## 5. 信息架构

页面与面板共 6 个：书架页、阅读页、目录抽屉、设置抽屉、导入浮层、错误提示。

阅读页布局分三区：顶栏（返回、书名、目录、设置）、正文区（可滚动）、底栏（本章进度、全书进度、上下章）。

## 6. 数据与状态

| 对象 | 主要字段 |
| --- | --- |
| Book | id、title、author、genre（EPUB / TXT）、cover、fileName、size、source、chapters[{title, blocks}]、addedAt、lastReadAt |
| Progress | bookId、chapter、percent、lastReadAt |
| Settings | theme、fontSize、leading、width |

- v1 的实现：整份状态（书架、进度、设置、导入书正文）序列化进 `localStorage` 的 `yejian.state.v1`，写入失败时先丢正文保住进度与设置，并提示重新导入。
- 目标形态：书籍正文与进度迁到 IndexedDB，`localStorage` 只留设置，见 `TECH_DESIGN.md` 第 9 节。

状态流：`空书架 → 导入中 → 书架 → 阅读中 → 书架`。导入中失败回到书架并提示原因，不阻塞其他书。

## 7. 非功能需求

- **隐私**：不上传任何书籍内容或阅读行为，全部留在本机。
- **离线**：除首次加载页面外不依赖网络。
- **性能**：单章渲染不阻塞输入；书库 50 本时书架首屏仍流畅。
- **兼容**：Windows / macOS 上的 Chrome、Edge 近两个大版本；以安装后的 PWA 形态运行，不做移动端。
- **响应式**：桌面优先，最小窗口 1024 × 700；≥ 900px 抽屉悬浮，窄于此抽屉覆盖正文。

## 10. 风险与未决问题

| 风险 / 问题 | 影响 | 处理方式 |
| --- | --- | --- |
| ZIP 解析是否引依赖 | 决定「零依赖」能否保持 | 桌面 Chrome / Edge 已支持 `DecompressionStream`，自研约 120 行，不引 JSZip |
| 位置记录的精度 | 影响「改字号不跳位」与 v0.2 笔记 | 用块序号 + 块内比例替代纯百分比，预留 CFI |
| 中文字体与断行 | 影响排版质感 | 只用系统字体栈，不引入外部字体 |
| PWA 文件关联的系统差异 | 双击打开依赖已安装的 PWA | 拖拽与选择文件始终作为主路径，文件关联只做增强 |
| 书籍版权 | 不涉及分发，风险较低 | 不提供书源，不做在线传阅 |
